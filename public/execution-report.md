# 智慧仓库 · GitHub Pages 执行报告

本报告记录仓库应用和本轮迁移的可核对操作、需求解释及决策摘要。内部逐字思维链无法提供；凭证和私人项目资料不纳入公开仓库。

## 一、原始链路

原始目标为带数据库的智慧仓库驾驶舱。初版实现了数据库持久化和业务闭环，后续把 CSS 透视替换为 Three.js/WebGL 实体模型。Sites 访问受阻后，用户要求改用 GitHub Pages，并明确选择“先发布可操作演示版：数据保存在各浏览器本地，不能跨设备同步”。

历史开发使用 Sites 建站与托管技能。本轮改用 GitHub Pages，没有继续使用 Sites 发布工具。使用本机命令工具检查 GitHub 授权、创建独立工程、安装依赖、运行测试与构建，使用 GitHub CLI 配置仓库及 Pages，用 GitHub Actions 部署。原工程保留完整逐轮报告。

## 二、需求理解

页面包括真实 3D 首页、库位库存、出入库记录、移库补货任务、预警中心和本报告。数据对象包括商品、库位、库存、流水、任务和演示人员。200 个库位使用四种状态颜色；货物高度体现数量；悬停显示商品，点击打开明细与流水。

主管创建和指派任务，理货员领取并完成；完成时在同一个 IndexedDB 事务内更新任务、库存和流水。数据范围按用户确认改为各浏览器本地。

## 三、执行步骤

1. 核对 GitHub 真实网络授权可用，检查仓库名称，避免覆盖既有项目。
2. 依据 GitHub 官方说明确认 Pages 为静态托管，向用户说明数据库限制；用户明确选择本地演示版本。
3. 从现有工程提取 3D 模型、页面和样式到独立 Vite/React 项目；只保留模拟业务数据，不上传旧私人站点配置与密钥。
4. 将接口访问改为 IndexedDB 本机数据库事务，保留创建、领取、完成、出入库、容量检查和重复完成保护；新增醒目的数据范围提示和重置入口。
5. 配置 hash 导航和相对资源地址以适应 GitHub Pages 子路径，新增 GitHub Actions 测试、构建和部署工作流。
6. 测试低库存 A2-03-05 → 指派小王 → 领取 → 补货完成，数量从 9 件增至 33 件；核对错误身份、并发重复完成、库存不足、超容量及移库一入一出流水。

## 四、关键决策

- 保留原服务端版本，单独发布用户确认的本地演示版。
- 使用 IndexedDB 数据库事务；任务完成及库存流水写入一起提交，失败一起回滚。
- 状态由库存合计与安全阈值推导，三维图每 3 秒回读本机数据，当前操作后立即回读。
- 不发布包含私人工作区信息的历史报告；本公开报告保留需求、步骤、技术取舍和证据边界。
- 三维是实体几何与相机交互，没有接入真实仓库 CAD/BIM 或实测尺寸。
